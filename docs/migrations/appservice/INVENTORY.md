## Summary

46 commands (42 contributed A+B + 4 contributed with no handler + 3 code-only B), 17 settings, 17 live tree node types (9 extension-owned + 8 shared) + 3 legacy unused classes (+ variants and status/invalid placeholders), 3 AzureWizard flows (create web app with basic/advanced modes, create slot, delete) + 1 programmatic create flow (deploy image) + the deploy pipeline and 6 smaller interactive flows, 0 debuggers, 0 task providers/definitions, 0 problem matchers, 0 jsonValidation, 0 viewsContainers, 0 views, 1 submenu, 78 menu entries (58 on `view/item/context`), 1 orphan NLS key.

The extension is a thin composition layer: most behavior (deploy pipeline, create wizards, Kudu/ARM site operations, app-settings tree, files/logs/deployments tree, remote debug, log streaming, delete/swap) lives in the shared libraries `@microsoft/vscode-azext-azureappservice` and `@microsoft/vscode-azext-azureappsettings`, and is inventoried here as part of the feature surface.

## 0. Extension-level shape

- extensionDependencies: `ms-azuretools.vscode-azureresourcegroups`. The extension obtains the host API with `getApiExport('ms-azuretools.vscode-azureresourcegroups').getApi('0.0.1')`; if absent it throws `Could not find the Azure Resource Groups extension`.
- engines.vscode: `^1.106.0`; `preview: true`; category `Azure`; entry `./main.js` (loads `dist/extension.bundle`, measures bundle load time into `mainFileLoad`).
- activationEvents (A): `onFileSystem:azureAppService`. Activation is otherwise driven by `x-azResources.activation.onResolve`.
- capabilities: none declared (`virtualWorkspaces` / `untrustedWorkspaces` absent). No command carries an `enablement` gate (`!isWeb` / `!virtualWorkspace` not used).
- enabledApiProposals (A): `terminalDataWriteEvent` (also typings `vscode.proposed.authLearnMore.d.ts`, `vscode.proposed.authenticationChallenges.d.ts` are present).
- x-azResources (A, under `contributes`): `azure.branches[0].type = AppServices`; `commands[0]` = `appService.CreateWebApp` (type `AppServices`, title/detail from `appService.createWebAppTitle` / `appService.createWebAppDetail`); `activation.onResolve = ['microsoft.web/sites']`. No `workspace` contribution.
- Exported extension API (B): `activate()` returns `createApiProvider([{ revealTreeItem, apiVersion: '1.0.0' }])`. `revealTreeItem(resourceId)` (telemetry callback `api.revealTreeItem`) calls `ext.rgApi.tree.findTreeItem(resourceId, { loadAll: true })` then `reveal(node, { select: true, focus: true, expand: true })`; unknown ids are silently ignored. Typings: `src/vscode-azureappservice.api.d.ts` (`AzureAppServiceExtensionApi { apiVersion: string; revealTreeItem(resourceId: string): Promise<void> }`).
- Activation wiring (B), inside `callWithTelemetryAndErrorHandling('appService.activate')` (sets `isActivationEvent = 'true'` and `mainFileLoad`):
  1. `createAzExtOutputChannel('Azure App Service', 'appService')`, then `registerUIExtensionVariables`, `registerAzureUtilsExtensionVariables`, `registerAppServiceExtensionVariables`.
  2. `registerCommands()` (section 1).
  3. `registerErrorHandler(c => c.errorHandling.suppressReportIssue = true)` -- the per-error "Report Issue" button is suppressed for all errors in favor of the command; `registerReportIssueCommand('appService.ReportIssue')`.
  4. `ext.rgApi = getResourceGroupsApi()`; `registerApplicationResourceResolver(AzExtResourceType.AppServices, new WebAppResolver())`.
  5. `workspace.registerFileSystemProvider('azureAppService', new AppServiceFileSystem(ext.rgApi.tree))`.
  No debug/task/language providers, no authentication session at startup, no experimentation service.
- Telemetry (B): EventName convention `<extensionId>/<callbackId>` (lowercased). Per-feature usage is collected once via the generic query and shown in the Usage Summary + each feature's Telemetry cell. Instrumented callbacks beyond commands are listed in section 9. No callback sets `suppressIfSuccessful` or `suppressAll`; `suppressDisplay` is set by `appService.validateWebSite`, `linuxWebAppDownDetector`, `appService.streamingLogs`, and by the deploy failure survey; `suppressReportIssue` is set globally (activation), by `OperationNotSupportedError`, by `DeployImageCreateStep` (Arc admin-credential error), and by `registerSiteCommand` for HTTP 502/503.
- Azure SDKs (B): `@azure/arm-appservice`, `@azure/arm-appinsights`, `@azure/arm-authorization`, `@azure/arm-resourcegraph`, `@azure/arm-resources` (and `@azure/arm-operationalinsights` through the shared lib), plus `dotenv`, `fast-xml-parser`, `open`, `@opi-perf/json`.

## 3. Tree view (A branch + B behavior)

- Registered under views: none contributed by this extension. It contributes an Azure Resources **branch** (`AppServices`) to the host's `azureResourceGroups` / `azureFocusView` views, and a submenu to `view/title` for `azureWorkspace`. Resolver: `WebAppResolver` for ARM `microsoft.web/sites` (AzExtResourceType `AppServices`).
- Resolver (B): Resource Graph query `resources | where type == 'microsoft.web/sites' and kind !contains 'functionapp' and kind !contains 'workflowapp'`, paginated with `skipToken`; 3-second cache keyed by lower-cased resource id; falls back to `webApps.get` when Resource Graph does not yet list a newly created app; tracks duplicate names to show a location description when grouped by resource type. `matchesResource` rejects `functionapp` kinds. Telemetry callback `resolveResource`. Returns `ResolvedWebAppResource` with `contextValuesToAdd = ['azAppWebApp']` (or `['azAppSlot']` for a slot) and `instance: 'resolvedWebApp'`.

## 4. Debugging + tasks (A + B)

- Debuggers (A): none contributed. Task providers (B): none. taskDefinitions / problemMatchers (A): none. Dev-server/emulator addresses: none.
- Remote debugging (B) is driven by a dynamic `launch` configuration, not a contributed debugger: `appService.StartRemoteDebug` gates on Linux Node.js (>= 8.11) and, behind `appService.enablePythonRemoteDebugging`, Linux Python. Errors: `Azure Remote Debugging is currently only supported for Node.js version >= 8.11 on Linux.`, `... only supported for Node.js and Python apps on Linux.`, `... only supported for Node.js apps on Linux.`. The shared flow toggles `siteConfig.remoteDebuggingEnabled`, starts a `TunnelProxy`, attaches with the VS Code debug adapter for the runtime, and restores config afterward (callbacks `appService.remoteDebugUpdateConfiguration`, `appService.remoteDebugStartProxy`, `appService.remoteDebugAttach`; progress text `Fetching site configuration...`).
- SSH (B) -- `appService.StartSsh`: Linux only (`Azure SSH is only supported for Linux web apps.`); guard `Azure SSH is currently starting or already started for "{0}".`; `Checking app settings...`; if remote debugging is on: `Remote debugging must be disabled in order to SSH. This will restart the app.`; picks a free local port; starts `new TunnelProxy(localPort, site, credentials, true)` against the SCM tunnel to container port 2222; opens an integrated terminal running `ssh root@127.0.0.1 -p <port>` with `-c aes256-cbc`, `StrictHostKeyChecking=no`, `UserKnownHostsFile /dev/null`, `LogLevel ERROR`; auto-enters the container password (`Docker!`) by watching terminal output (uses the `terminalDataWriteEvent` proposed API); disposes the tunnel and session when the terminal closes (`Azure SSH for "{0}" has disconnected.`).

### 5.1 Create web app -- `appService.CreateWebApp` / `appService.CreateWebAppAdvanced` (`createWebApp.ts`)

Configurable inputs that must survive: location, domain-label scope, resource group (advanced), name, OS/stack/version (+Java server), custom location, plan (new/existing, SKU, zone redundancy), Application Insights (new/existing/none), profiler flag. Outputs consumed after creation: created `Site` (activity result), plan id, Application Insights connection string.

Post-execution: activity label `Create web app "{0}"`, success `Successfully created web app "{0}": {1}`, failure `Failed to create web app "{0}"`; resource tree refreshed; Windows file logging enabled afterward (failure is non-blocking -> telemetry `fileLoggingError`); `showCreatedSlotMessage` (callback `postCreateWebApp`, telemetry `dialogResult`). Telemetry properties: `newSiteOS`, `newSiteStack`, `newSiteMajorVersion`, `newSiteMinorVersion`, `newSiteJavaStack`, `newSiteJavaMajorVersion`, `newSiteJavaMinorVersion`, `planSkuTier`, `enableProfiler`, `siteDomainNameLabelScope`, `performanceWarning`, `turnOffPerfWarning`, `getStacksError`, `fileLoggingError`, `dialogResult`, `hasAz<property>Default`.

### 5.2 Create deployment slot -- `appService.CreateSlot` (shared `createSlot`)

Prompts: (1) slot name `Enter a unique name for the new deployment slot` (min 2 chars, combined site+slot name <= 59, letters/numbers/hyphens only, `production` rejected, ARM availability check with suffix `Slot`; messages `The slot name "{0}" is not available.`, `The slot name must be at least {0} characters.`, `The combined site name and slot name must be {0} characters or fewer.`, `The name can only contain letters, numbers, or hyphens.`); (2) configuration source (`Choose a configuration source.`: `Don't clone configuration from an existing slot`, production, each existing slot; Function Apps skip the prompt). Execute `DeploymentSlotCreateStep` (priority 250): `webApps.beginCreateOrUpdateSlotAndWait` on `Microsoft.Web/sites/{site}/slots/{slot}`, payload copies `kind`, `location`, `serverFarmId`, empty `siteConfig.appSettings`, then clones app settings from the chosen source (Function Apps replace `WEBSITE_CONTENTSHARE`). Resource: `Microsoft.Web/sites/slots` (child of the parent site, same plan).

### 5.3 Delete -- `appService.Delete` (`ResolvedWebAppResource.deleteTreeItem`)

Prompt steps: `DeleteConfirmationStep` (separate messages for web app vs slot) and `DeleteLastServicePlanStep` (shown only for non-slots: when the plan's `numberOfSites < 2`, modal `This is the last app in the App Service plan "{0}". Do you want to delete this App Service plan to prevent unexpected charges?`). Execute `DeleteSiteStep` (priority 100): `Deleting web app|slot|function app "{0}"...`, `client.deleteMethod({ deleteEmptyServerFarm })`, `Successfully deleted ... "{0}".`.

### 5.4 Deploy image -- `appService.deployImageApi` (programmatic)

Inputs (required, else `Missing required deploy image options. Expected image, registryName, repositoryName, and tag.`): `image`, `registryName`, `repositoryName`, `tag` (optional `username`, `secret`, registry resource). Prompts: location, site name, resource group, custom location, `ContainerPortStep` (custom location only: `Enter the port that the container listens on`, default `80`, integer 1-65535, `Please enter a valid port number (1-65535)`), App Service plan list. Execute: `VerifyProvidersStep(['Microsoft.Web'])`, `DeployImageCreateStep` (140), `AssignAcrPullRoleStep` (141; ACR, non-Arc), `CreateWebhookStep` (142; ACR or Docker Hub).

Provisioning record: primary `Microsoft.Web/sites`, `kind` `app,linux` (+`,kubernetes,container` for custom location), `reserved: true`, `clientAffinityEnabled: true`, `serverFarmId`; ACR non-Arc: `acrUseManagedIdentityCreds: true`, `DOCKER_ENABLE_CI=true`, `identity.type = SystemAssigned`, `linuxFxVersion` deferred until after role assignment; `AssignAcrPullRoleStep` lists the `AcrPull` role definition at the registry scope, creates `Microsoft.Authorization/roleAssignments` (random UUID name, principal = site identity, `principalType: 'ServicePrincipal'`), then `webApps.updateConfiguration({ linuxFxVersion: 'DOCKER|<image>' })`. ACR on Arc: requires admin `username`/`secret` (`Admin credentials are required for deploying ACR images to Azure Arc. Enable the admin user on registry "{0}" in the Azure Portal under Access keys, then try again.`), sets `DOCKER_REGISTRY_SERVER_USERNAME`/`_PASSWORD`/`_URL=https://<registry>`, `WEBSITES_PORT`, `linuxFxVersion=DOCKER|<image>`. Docker Hub/other: same registry app settings (`WEBSITES_PORT` only for custom locations). Webhook: calls `webApps.updateScmAllowed({ allow: true })` and `beginListPublishingCredentialsAndWait`; ACR -> raw ARM PUT `Microsoft.ContainerRegistry/registries/webhooks` (api-version `2023-07-01`; name = site name stripped of non-alphanumerics, truncated to 44 chars + 6 random hex; `serviceUri = <scmUri>/api/registry/webhook`, `scope = <repo>:<tag>`, `actions: ['push']`, `status: 'enabled'`); Docker Hub -> no ARM resource, message `To enable CI/CD, add the webhook URL in Docker Hub. Select "{0}" to copy the URL and open Docker Hub.` (button `Copy & Open`, opens `https://cloud.docker.com/repository/docker/<repo>/webHooks`). Post-create: tree refresh, `Successfully created web app "{0}".` with `Browse Website`. Activity title `Deploy Image to Web App "{0}"`.

### 5.5 Deploy -- `appService.Deploy` / `appService.DeploySlot` (flow, not an `AzureWizard`)

Ordered flow (`deploy.ts`): initialize telemetry (`deployedWithConfigs`, `defaultAppSetting = 'defaultWebAppToDeploy'`) -> `setPreDeployConfig` -> `getDeployNode` (picks app/slot) -> init site + `SiteClient`; set `correlationId`, `siteLocation`, `siteDomainNameLabelScope` -> get site config -> Java SE settings for Java runtimes -> deploy method (zip unless `scmType` is `LocalGit` or `GitHub`) -> optional SCM-build prompt (below) -> confirmation (`appService.showDeployConfirmation`; non-new app, zip deploy): `Are you sure you want to deploy to "{0}"? This will overwrite any previous deployment and cannot be undone.` -> fire-and-forget `promptToSaveDeployDefaults` -> run `appService.preDeployTask` -> cancel any previous Linux detector for the app -> node description `Deploying...` -> shared `appservice.deploy(...)` (non-zip deploys ignore `deploySubpath`: `WARNING: Ignoring deploySubPath "{0}" for non-zip deploy.`) -> on failure `failureMoreInfoSurvey` (may set `suppressDisplay`) -> `showDeployCompletedMessage` -> async post-deploy task / Linux detector.

Deploy path resolution (shared `getDeployFsPath`): workspace folders, explorer-selected folders, `.zip`, `.war`, `.jar`, `.dll`, `.csproj`, `.fsproj`; deploy-subpath mismatch warning (`appService.showDeploySubpathWarning`, callback `deployWarning.openInNewWindow` with `Open in new window`).

Shared pipeline (`createDeployWizard`): zip deploy (glob/ignore settings `appService.zipGlobPattern` / `appService.zipIgnorePattern`), WAR deploy (`kuduClient.warPushDeploy`, error `Path specified is not a war file`), JAR deploy, local-git and GitHub deploys, storage-account/run-from-package variants (`WEBSITE_RUN_FROM_PACKAGE`, `WEBSITE_RUN_FROM_ZIP` are recognized), Function App variants. Kudu polling (`waitForDeploymentToComplete`): `getDeployResult` / `getDeployResults` / `getLogEntry` / `getLogEntryDetails` through `retryKuduCall`, 60-second initial Kudu window, final log line used for concise failure messages.

Pre-deploy configuration (`setPreDeployConfig`; skipped when `showPreDeployWarning` is false, or `preDeployTask` or `deploySubpath` already set): .NET (`tryGetCsprojFile` records `csprojInSubfolder`, `numOfCsprojFiles`; sets `appService.preDeployTask` to a publish task and `appService.deploySubpath` to `<subfolder>/bin/Release/<targetFramework>/publish`, telemetry `tfw`); Maven (`tryGetMavenModule`; sets the Maven package task and `deploySubpath = <module>/target/<artifactFinalName>`). Prompt `Required configuration to deploy is missing from "{0}".` with button `Add Config`; the generated `.vscode/tasks.json` / `settings.json` content comes from `vsCodeConfig/tasks.ts` / `settings.ts`.

SCM build prompt (`promptScmDoBuildDeploy`): shown when `showBuildDuringDeployPrompt` is true, Linux Node/Python, zip deploy, no `.deployment` file, and `SCM_DO_BUILD_DURING_DEPLOYMENT` not already set: `Would you like to update your workspace configuration to run build commands on the target server? This should improve deployment performance.` (telemetry `enableScmInput` = `Canceled`/`Yes`/`No`); on Yes it updates `appService.zipIgnorePattern` and writes `.deployment` containing `[config]` / `SCM_DO_BUILD_DURING_DEPLOYMENT=true`; it disables itself by setting `showBuildDuringDeployPrompt` false.

Save defaults (`promptToSaveDeployDefaults`): `Always deploy the workspace "{0}" to "{1}"?` with `Don't show again` / `Yes` / `Skip for now` (telemetry `promptToSaveDeployConfigs` = `Yes`, `Don't show again`, `Skip for now`, `None`, `usesDefault`); Yes writes `appService.defaultWebAppToDeploy` (full site id) and `appService.deploySubpath`.

Completion (`showDeployCompletedMessage`, callback `postDeploy`): `Deployment to "{0}" completed.` with `Browse Website`, `Stream Logs`, `Upload Settings` (telemetry `dialogResult`).

Post-deploy checks (async): `appService.validateWebSite` (pings the site; sets `suppressDisplay`); `linuxWebAppDownDetector` (Linux only): reads latest Kudu deployment (`getDeployResult(..., 'latest')`), polls up to 5 minutes every 10 seconds `GET <siteId>/detectors/LinuxLogViewer?api-version=2015-08-01&startTime&endTime&logFormat=plain`, parses `insight/logs`, prefers `application/insight` then `docker/insight`, requires status `Critical`, shows `"{0}" reported a critical error: {1}` with `View details` (callback `viewedDetectorDetails`) which opens the portal troubleshoot blade `websitesextension_ext=asd.featurePath%3Ddetectors%2FLinuxLogViewer`; telemetry `correlationId`, `lastStep = 'noDeployResult'`, `timedOut`, `viewed`, `insight` (`app`/`docker`), `errorMessages`, `timeBetweenDeployAndDetector`, `invalidTimestamp`. `appService.postDeployTask` runs after zip deploys (shared `PostDeployTaskExecuteStep`).

Deployment source commands: `appService.ConfigureDeploymentSource` -> shared `editScmType` (`ScmType` `None` / `LocalGit` / `GitHub`; refreshes the Deployments node); `appService.connectToGitHub` -> `editScmType` with `GitHub` (shared GitHub flow: auth, repo + branch pick, ARM source-control creation); `appService.DisconnectRepo` (`This app is not connected to any repository.` / `UserCancelledError('notConnectedToRepo')`, else shared `disconnectRepo`); `appService.Redeploy`, `appService.viewDeploymentLogs` (via `registerSiteCommand`); `appService.ViewCommitInGitHub`.

## Migration-relevant cross-cutting notes

- Host-API dependence: tree rendering, resolver registration, `pickAppResource`, activity log, and tree refresh all go through the Azure Resources host API; the monorepo owns those natively (DataItemTree/ViewItemTree providers rather than `AzExtTreeItem`).
- Shared-library coupling: the real implementation of deploy, create (plan/App Insights/Log Analytics/stack steps), slots, delete, swap, remote debug, log streaming, Kudu VFS, deployments and app settings is in `vscode-azuretools` (`appservice`, `appsettings`); migration must re-implement these features rather than depend on those packages.
- Contract between menus and nodes: contextValue regexes depend on the sorted `;`-joined composition (`appService;...`); in the monorepo these map onto `ManagedCommand` static `ContextValue`s with `\b` regexes. The `azAppWebApp` / `azAppSlot` split (apps vs slots) drives which commands appear.
- Dual surface: commands are reachable from the tree, the palette (with a pick flow when no node is supplied), `explorer/context` (deploy, upload `.env`), the workspace view submenu, and one programmatic API command (`appService.deployImageApi`) plus the exported `revealTreeItem` API.
- Creation topology maps onto an azd/Bicep creation flow (plan, optional workspace + Application Insights, site, optional slot and role assignment); AVM selection is performed by the migration skill, not here.
- Defaults live in settings (`defaultWebAppToDeploy`, `deploySubpath`, `preDeployTask`, `postDeployTask`, `zipGlobPattern`, `zipIgnorePattern`, `show*` prompts); the monorepo's shared settings framework (adapters, JSONC editor) is the likely home.
- Dead surface to exclude: all Cosmos DB connection features, `appService.connections`, `appService.showExplorer`, the legacy `AzureAccountTreeItem` / `SubscriptionTreeItem` path, `NotAvailableTreeItem`, and the unreferenced `appService.LoadMore` NLS string.
